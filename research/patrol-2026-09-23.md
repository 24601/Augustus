- **Source:** `https://github.com/typesafe-ai/skills/issues/6` (read

- **Prior:** first sighting of the issue and the schema.
- **Observed:** the issue (2026-09-21) reports that a one-level Score returns
  200 with confidence 1.0, and 11 levels return 400. The schema gives
  `ScoreQuestion.criteria` minItems 1 with no maximum, leaves Choice criteria
  unbounded, and declares only 200 and 422. The prose API page says a Score
  should have at least two levels and accepts up to 10, and caps Choice at 255
  options. Python accepts a one-level Score; JS rejects fewer than two.
- **Status:** Contract for schema, docs and SDK source; Reported for live
  behavior.
- **Claim:** one reporter on `jev-latest` → jev-1.13.0; no sample.
- **Limitations:** not reproduced, and no live endpoint was called. Whether a
  one-option Choice is accepted is Unknown.
- **Implication:** any concentration statistic over one outcome is maximal, so
  1.0 compares nothing. A dynamically built menu can present one candidate, and
  a confidence-gated policy would act on it. Counterexample: a closed hierarchy
  with one child is legitimately certain; the official hierarchical cookbook
  resolves `len(labels) == 1` in code without a model call.
- **Disposition:** refine-reference.
- **Target and falsifier:** `references/question-design.md` preflight. The
  finding is falsified if the API rejects fewer than two options or levels, or
  returns non-maximal confidence for them.

**TypeLLM fair-die study: position bias versus label prior**

- **Source:** `https://typellm.ai/blog/fair-die` (dated 2026-09-22, full text),
  README at `d592c10`, which adds a `permutations` parameter.
- **Prior:** §113 for TypeLLM; first sighting of the study.
- **Claim (theirs):** one context, "a single roll of a fair die", six options,
  all 720 orderings. Jev 1.13 put top mass on the label "one" in 720/720
  orderings (77–91%). TypeLLM with Qwen3.8-27B put top mass on the first
  position in 718/720. The 720-order means were 86.01% on "one" for Jev and
  13.47–25.41% per face for Qwen. Separately, Jev-Omni's own
  `verification_unified.json` gives a fair die
  0.234/0.093/0.044/0.089/0.081/0.459.
- **Local arithmetic on their means:** KL to uniform is about 1.191 nats for Jev
  and 0.0275 for Qwen.
- **Status:** Reported.
- **Limitations:** n = 1 context, run by the author, raw responses not
  inspected. Jev's documented confidence is concentration, so whether Choice
  mass should encode outcome frequency is a semantics question. The cause of
  the label preference is not identified.
- **Mechanism:** full-group averaging makes output invariant to presentation
  order, so it cancels position bias. A prior tied to label identity moves with
  the label and survives averaging. Order shuffling alone never reveals it.
- **Counterexample:** with semantically distinct options, a winner stable
  across orders is correct behavior. The diagnosis needs a case whose answer
  distribution is known.
- **Disposition:** refine-reference.
- **Target and falsifier:** `references/composition-algebra.md`, Averaging
  option permutations. Falsified if full-order averaging removes skew for a
  label-following model on frozen, known-symmetric cases.
