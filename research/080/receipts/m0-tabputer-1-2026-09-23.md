## Deviations from plan v3 found here (fold into v4)

1. **Principal uids are 48201 and 48202, not 1001 and 1002.** Host uid 1001 is used by fleet-pr
   runner containers.
2. **The container profile gains `--memory-swap=16g`.** Without it, the memory cap is not a cap
   on this host.
3. **The launch mechanism is `systemd-run --user` inside `augexp`'s user manager**, never
   `sudo -u … podman` from another session (B15).
4. **Local IPC and world-readable trees of other workloads are part of the boundary**, handled by
   `augipc-acl`, `augustus.conf` and `augfs-deny`. §4.6 adds a non-claim: new world-readable
   trees created later by other workloads are covered only when B4 and B5 are rerun.
5. **Proxy SNI binding** was added. §4.6 adds a second non-claim: domain fronting through a CDN
   that allows a Host header different from SNI.
6. **The base image is the local vLLM ROCm image** (decision 23 answered). The GPU path passes
   for torch/transformers and for batched vLLM with standard attention. Qwen3.5 linear-attention
   kernels are untested.
8. **GPU memory needs its own budget.** GTT is not charged to the container cgroup (see above).
9. **E4a (a 9-hour stdlib Monte Carlo) moves to a vectorized GPU implementation** under D-b, or v4
   states why a CPU step remains.
7. **The allowlist is currently** `pypi.org`, `files.pythonhosted.org`, `huggingface.co`, and
   `us.aws.cdn.hf.co`, the last a recorded edit taken from the refusal log.

## Not claimed

Everything in plan v3 §4.6 still stands. There is no protection against root, the maintainer's
account, privileged k3s workloads, or kernel and GPU-driver exploits. `/dev/kfd` and
`renderD128` are 0666 host-wide. The boundary is exactly what these tests exercised, and it must
be retested after any system update.
