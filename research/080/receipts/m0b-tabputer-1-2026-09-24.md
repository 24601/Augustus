Operator: an Amp thread on the runner `tabputer` (`/mnt/tst`, user `basit`), mode `gpt6a-med`,
thread `T-01a0d211-2f96-76ef-8c5c-895889473926`. Source at `ccf7a1a` on
`research/080-exopo-trainer`. Coordinator decisions in that thread are quoted where they changed
the work.

**Result: B16, B17, B18 and B20 pass; B19 fails, which is a measured answer the plan already

`augctl` reaches its publication targets through a traverse-only ACL (`u:augctl:--x`) on the three
stage parents, which keep 0750 root:augexp. Publication subdirectories underneath are augctl-owned
0750. After the ACL change, B6 and B11 were re-run: `augexp` still cannot read `/srv/aug/ctl`
(errno 13), and `augctl` still reached no network on any probe.

**A provisioning attempt was reverted.** Before the coordinator's instruction arrived, the runner
had begun allocating `augctl` a subuid/subgid range so it could run rootless containers. That was
blocked: `augctl` is the only principal that ever holds confirmation labels, and every capability
it gains sits next to them. The mappings were removed, the started load was cancelled, the
newly-created container storage and its temporary directory were deleted, and all custody
thereafter ran as `augctl` directly on the host, never in a container. Verified afterwards:
`augctl` has no subordinate id allocations and no container storage.

## Storage incident, recorded in full

B17 was first attempted with a 2 GiB preallocated NOCOW loop-mounted ext4 image at
`/srv/aug/runs.img`, with the existing 334 MB of run directories preserved at
`/srv/aug/runs.pre-m0b` and copied in with a verified diff. The fill hit ENOSPC correctly at
1,672,478,720 bytes. Afterwards, `sudo sync -f /srv/aug/runs.img` returned
`sync: error syncing '/srv/aug/runs.img': Structure needs cleaning` (EUCLEAN). The runner stopped
all disk activity at that point, which was the right call.

Host health, checked read-only: `btrfs device stats /` showed `corruption_errs 57` with zero
read, write, flush and generation errors. Dating it:

- the current boot began **2026-09-23 18:50 MDT**, before M0 and covering all of M0b;
- this boot's kernel journal contains **zero** btrfs entries, and btrfs logs csum failures at
  error level;
- the counter is cumulative across boots and the only other boot in the journal is 2026-07-28.

So the 57 errors predate this boot and therefore predate this work. **The `EUCLEAN` itself remains
unexplained**: `sync -f` syncs the containing filesystem, which is the host btrfs, yet the kernel
logged nothing. No repair, fsck, scrub or reboot was performed, and whether to scrub 1.21 TiB is
the maintainer's decision at the console.

The image was then unmounted read-only, auto-detached, and deleted; `/srv/aug/runs` was restored
from the preserved copy, diff-verified clean, confirmed `augexp:augexp 0700`, and the backup
removed. **The design changed as a result:** `/work` is now a sized tmpfs, so a run never writes
to the host disk and there is no second filesystem implementation underneath the experiments.
