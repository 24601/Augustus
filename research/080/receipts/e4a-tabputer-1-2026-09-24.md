## Three bugs the gates caught, in order

This is the part worth keeping. None of them would have been visible in a receipt that said
"all cells qualify", which is exactly what the first attempt said.

1. **The parity gate stopped the first run outright.** All 32 empirical-Bernstein comparisons
   mismatched while all 32 Hoeffding ones agreed. Cause: the research branch had never been merged
   with `main`, so it still carried the 0.7.2 helper, which computes Hoeffding and strict
   superiority and ignores `mode` and `method` entirely. E4a was checking its EB arithmetic
   against a helper with no EB. Fixed by merging `main` into the branch, and the re-run now
   pre-checks that the staged helper contains the EB path.
2. **Parity compared bounds while claiming to compare verdicts.** Two implementations can agree on
   a number and disagree about what it means. Parity now checks the bound *and*
   `strict_margin_supported`, and says which of the two differs.
3. **The sign-flip control was a no-op.** The first full run showed zero adoptions for
   `delta_sign_flipped` in all four cases. The mutation was `-values + 2*boundary`, which reflects
   a symmetric draw about its own boundary mean and leaves the null distribution unchanged.
   The real defect is Δ computed as incumbent − candidate, so the mean changes sign.

   Fixing it exposed a second error, in the **design lock** rather than the code: a sign flip is
   only visible when the interval radius is below twice the margin. At margin 0.05 the radius is
   0.141 (Hoeffding) and 0.167 (EB) at n = 300, against 0.049 and 0.042 at n = 2,500. Planting it
   at n = 300 could never have detected it, and naming the mode without naming n would have made a
   correct implementation look like a miss.

   And `planted_defects_detected` used `any(...)`, which lets a missed detection hide behind a
   successful one. Each case now carries its own expectation, including the superiority rows that
   must show nothing, and the script exits nonzero if any case does not meet it.

The runner also noted that a "must not detect" row accepted any rate below the tolerance rather
than exactly zero. Theory says exactly zero there, since UCB(+m) > −m on every replication, so the
expectation is now `expected_max_rate = 0.0` for those rows. This run satisfies the stricter test.

## What this establishes, and what it does not

It establishes that at these 108 cells the implementation has no gross defect, and that the
diagnostic is capable of failing, which the planted defects demonstrate.

It does **not** establish coverage. That claim rests on the theorems and the exact-rational unit
tests. `sign_exact` cells are exact arithmetic rather than simulation, and their computed sizes
(0.0472 at n = 2,500, q = 0.5, K = 1) independently reproduce the Fable v3 review's 0.047184.
