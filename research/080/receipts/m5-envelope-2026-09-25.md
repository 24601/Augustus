The accelerator is not the constraint for anything. A2a and A2b miss only a python package; R3a
misses only a python package; R1 and R2b miss only a checkpoint.

**The comparator is now reachable, and the remaining gap is a different kind.** A2a and A2b are
not missing an acquisition. The PAW compiler is not a Python package, its README requires an
NVIDIA GPU with BF16 support of Ampere or newer, and the SDK's runtime is a source build of
llama.cpp with GPU wheels behind a private index. tabputer is gfx1151. So those two rungs are
unreachable **in principle on this accelerator**, which
[`sources/paw-rap-2026-09-23.md`](../sources/paw-rap-2026-09-23.md) records as a finding rather
than an obstacle: a rung that compiles on one vendor's hardware and serves through a private index
is a rung most agents cannot climb, whatever its accuracy.

## Why this is being recorded rather than worked around

The obvious moves are all excluded, and each for a reason worth stating:

- **Installing `setfit` and `paw` into the image** breaks the pinned-image rule and the no-install
  rule. A pinned image whose contents change to suit an experiment is not a pinned image.
- **Running A1 and R2a and calling it the family** is what plan v4 §3.7 forbids in as many words:
  a silently reduced family turns "the cheap rung sufficed" into a statement about the hardware.
- **Substituting a staged Qwen3-1.7B or Qwen3-4B for the registered readout** would change a
  registered arm after the lock. They are different models — `qwen3`, hidden sizes 2048 and 2560 —
  and the probe reports those figures rather than asserting a conclusion.

What would change the answer is an acquisition decision the maintainer owns: an approved image
carrying `setfit` and `paw`, plus a bounded download of Qwen3.5-2B-Base. That is a real and
tractable path; it is not one to take silently mid-experiment.

## What this does not say

- It does not say any rung is bad. A missing package is an acquisition, not a result.
- It does not say the reachable rungs would pass the gate. Reachability is about fitting.
- It says nothing about the host: an earlier host probe reported torch absent, which was true of
  the host and irrelevant to the image. The program now requires the environment to be declared
  and refuses to have a host probe's verdict believed.
- The readout is identified by name, from `_name_or_path` or the directory. Both staged Qwen
  configs carry a null `_name_or_path`, so the directory did the work here. A correctly staged
  Qwen3.5-2B-Base carrying neither would be refused, and no config field distinguishes one 2B
  decoder from another reliably.
